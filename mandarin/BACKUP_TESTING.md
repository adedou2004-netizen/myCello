# Backup & Restore — test and release checklist

Branch: `feature/mandarin-to-go-local-first` · status: **implemented on branch, awaiting real-browser/device validation**

## What is implemented
- Backup button at top of `mandarin/index.html`.
- Download a locally assembled, uncompressed, versioned ZIP (no external JS ZIP dependency or database calls).
- Include application `localStorage` keys: `mandarinAppV2`, `mandarinExpressionsV1`, `rad60_i`, `rad60_done`, `hanzi-review`, `hanzi-current`, `mandarinPendingPinyin`.
- Include PNG/JPEG/WEBP/GIF personal Memory Card uploads saved in `mandarin-to-go-assets` IndexedDB; upload from a character's **Upload card** action.
- Import ZIP, verify format/checksums and source keys, show overlapping sections, choose **Merge** (preserve existing progress) or **Replace** (replace included sections), confirm, and reload.
- No auth secrets, payment data or unrelated localStorage keys are intentionally included.

- [x] Parse both changed JavaScript files.
- [x] Export -> inspect -> replace restores local state.
- [x] Merge safely retains existing SRS and adds vocabulary with different local IDs.
- [x] Union of radical progress on merge.
- [x] Reject tampered ZIP via CRC checksum.

- [x] Save local image blob -> backup ZIP -> restore image blob on a fresh simulated device.

## Mandatory browser/device verification before merging to main
- [ ] In Chrome desktop, open `mandarin/index.html` from the **feature branch** (local preview or branch deployment), add a word, change a review, download ZIP, confirm the file exists.
- [ ] In a clean browser profile, import and **Replace**; check lessons, examples, due dates, characters, expressions, radicals.
- [ ] Upload a personal card image, download backup, restore on a second browser/device, open the same card.
- [ ] Import twice using **Merge**: check no duplicate characters or expressions and unchanged existing progress.
- [ ] Cancel restore: nothing changes. Corrupt a ZIP: refused.
- [ ] On an actual phone, test file picker, downloaded ZIP location, import and large files.
- [ ] If the user accesses app from a different origin/custom domain, verify migration approach: localStorage is origin-scoped.
- [ ] Test loss-of-network behavior: JS backup engine is local and works; other app functions may still use remote resources.
- [ ] Confirm image storage permissions and quota on Safari and Android Chrome.
- [ ] Confirm the legacy root character page's storage keys in the original full file, especially if it uses additional variants.

## Known limitations and design notes
- ZIP files are deliberately **uncompressed**, so image backups may be relatively large; currently limited to 150 MB per export/import.
- Imported compressed ZIPs produced by other tools are not supported. Import the ZIP generated by Mandarin to Go itself.
- Only images explicitly stored through the new local Memory Card upload are bundled. Official hosted card images are not bundled; their URLs are stored in local entry records and will require connectivity to redownload.
- Merge preserves current values for unrecognized legacy keys; Replace handles included sections only (it does not erase unrelated keys).
- No cloud syncing or background auto-backup. Remind learners to download a backup periodically.
- We must still conduct a real browser/phone test and fix any issues before shipping to paying learners.

## How to preview without altering production
Check out `feature/mandarin-to-go-local-first` locally and serve repository root with a local HTTP server, then navigate to `/mandarin/`. The production `main` branch has not been modified.
